# Kernel discovery for q4 and q6

The frame Steinhardt call is the mutual four-nearest graph
(`candidate = cutoff + 1.5`, cutoff 3.5 A) on ideal ice Ic.
At 110592 molecules the previous call took 72.0 ms on one thread and
29.3 ms on eight. OVITO 3.17.2 q6 on the same size was 58.7 ms and
13.1 ms.

## Where the time went

A stage timer (`SEAMS_QL_TIME=1`) on the previous shape of the call,
one thread, 110592 molecules, l = 6:

| stage | ms |
| --- | --- |
| k-nearest nomination | 32–35 |
| mutual graph as atom-id rows, then a second minimum-image pass | 10–14 |
| Y_lm | 10–19 |
| ql and ql bar | 5–6 |

The atom-id rows are built on one thread, which is why eight threads
only reached about 2.5x. `OMP_PROC_BIND=close` also pins the calling
thread before Rayon starts, and the neighbour workers were inheriting
that single cpu.

## What landed

Even l needs no square root. With phi = atan2(x, y),

    Y_lm = S_lm(x, y, z) / r^l

and S_lm is a polynomial. For l = 4 and l = 6, r^l is a power of
r^2 = x^2 + y^2 + z^2. l = 3 still divides by r^2 * sqrt(r^2). The
polynomials are in `solid_ylm.hpp`. Bonds are not normalised first.

The frame path keeps the nomination in one n by k index array and the
coordinates in one n by 3 buffer. Each atom's mutual neighbours, the
minimum image, and the solid harmonic are one loop. ql bar reads that
same packed neighbour row. Buffers of a repeated size are kept and
refilled, which is what a run of timed calls does.

Before the neighbour pool is created, the calling thread's affinity is
widened to every cpu the kernel still allows, so a bind that pinned
the main thread does not pin the search. After the harmonics, the
OpenMP team is asked to stop spinning (`omp_pause_resource_all`) so
the next search gets the cores.

There is no minimax on the q4 or q6 path: the only operations are
arithmetic and, for the neighbour search, the existing cell walk.
A Sollya fpminimax of the leftover l = 3 reciprocal square root is
regenerated by `discovery/sollya_minimax.py`. It is not used for q4
or q6.

## Agreement

On 64 molecules of ideal ice Ic the packed call and the previous
neighbour-list call differ by at most 2e-16. pyscal3 4.1.0 with a
3.5 A cutoff agrees to the same tolerance:

| l | seams q_l | pyscal3 | max abs |
| --- | --- | --- | --- |
| 4 | 0.509175077217 | 0.509175077217 | 1.1e-16 |
| 6 | 0.628539361055 | 0.628539361055 | 4.4e-16 |

The neighbour-averaged values agree the same way. freud 3.6.1 stores
q_l as float32, so it sits about 1e-7 away, which is one float32 ulp
of these magnitudes, not a different harmonic.

`tests/test_ql_solid.cpp` checks the packed call against the
neighbour-list call to 1e-12 on ice Ic and on a disordered cloud
seeded with 91001, and checks the l = 4 solid harmonic against the
trigonometric table.

## Published CHILL+

The published cutoff rule (Nguyen and Molinero, closed edges
c_ij <= -0.8 and -0.35 <= c_ij <= 0.25) now evaluates the real l = 3
solid harmonic on the four nearest neighbours inside the CHILL+ call.
An orthogonal box is walked with a cell list that lives in that call.
The shared neighbour-list builder is not used and was not changed.
A non-orthogonal box still uses the existing pair search.

l = 3 needs one factor 1/(r^2 * sqrt(r^2)). The square root is the
correctly rounded hardware operation. On ideal ice of 64 molecules
and on two disordered clouds the labels and every c_ij match the
neighbour-list rule with a difference of 0. `tests/test_ql_solid.cpp`
checks the same agreement to 1e-12, including a cloud seeded with
91001.

## Sollya bounds

`discovery/sollya_minimax.py` writes
`discovery/generated/sollya_bounds.json` and
`src/include/internal/minimax_coeff.hpp`. Each number is the upper
endpoint of a Sollya `supnorm` enclosure (proof precision 1b-30 for
the function, 1b-20 for the derivative).

| approximant | interval | degree | supnorm |
| --- | --- | --- | --- |
| 2^{-x} relative | [0, 1] | 10 | 2.220446051253639e-16 |
| derivative of 2^{-x}, relative | [0, 1] | 10 | 7.781709175237108e-14 |
| 1/sqrt(x) relative | [1/2, 1] | 18 | 8.881784205014557e-16 |
| derivative of 1/sqrt(x), relative | [1/2, 1] | 18 | 2.245317119382296e-12 |
| ln(x) absolute | [1/2, 1] | 20 | 1.028838740165560e-17 |
| ln(x) relative | [1/2, 1] | 20 | 1.065814104601747e-14 |

The l = 3 path does not evaluate these polynomials. A degree-18
reciprocal square root is slower than a hardware square root, and the
hardware result is correctly rounded, which is why the checked c_ij
values differ by 0. The coefficient header keeps the analytic
derivative of each approximant beside the polynomial. q4, q6 and
CHILL+ do not call it.

## Symbolic pre-filter

`discovery/pysr_prefilter.py` fits a cubic indicator on sorted c_ij,
q3, the tetrahedral order and the neighbour radii. Training frames are
ideal ice Ic, ice with gaussian noise, and disordered liquids. Seeds
91001, 92002 and 93003 are held out, and so is one noisy ice cloud
drawn with seed 93003. Forty iterations, serial, seed 0. The Pareto
front, best loss last:

| complexity | loss | expression |
| --- | --- | --- |
| 1 | 0.08223 | qtet |
| 2 | 0.02647 | cmax^2 |
| 3 | 0.01857 | cmean^4 |
| 4 | 0.01628 | cmax^2 cmean^2 |
| 6 | 0.01610 | cmax^2 cmean^2 / 0.9840904 |
| 8 | 0.01532 | cmax^2 cmean^2 shell^2 / keep^2 |

The selected expression is cmean^4. At a threshold of 0.5 the held-out
accuracy against the published label is 1. The highest non-cubic score
in the whole set, training and held-out, is 0.8528497963226561, and no
non-cubic atom scores above it (0 false accepts, 1449 cubic accepts).

`chillPlusSymbolicPrefilter` is not on the default path. It labels
every atom cubic only when each atom has a shell of four and a
negative cmean whose fourth power exceeds that ceiling by 1e-6.
With every correlation in [-1, 1], cmean < -0.961 forces each of the
four correlations to be <= -0.84395, which is staggered at the
published edge -0.8. The atom is then cubic. A positive mean, a wider
shell, or a score on the boundary returns false and leaves the cloud
unchanged, so the caller runs the published rule. Ideal ice takes the
fast label. A liquid seeded with 91001 does not. Thresholds are
unchanged.

## After the cutoff-list rebase

`perf/kernel-discovery` is rebased onto `perf/neighbours-threads`
(`064bfef7`). q4 and q6 below are the mutual four-nearest call, which
builds that list inside the timed call. CHILL+ still walks its own
orthogonal cells. The shared CSR is not copied.

Eight-thread CHILL+ on 110592 molecules was bimodal, about 8 ms and
about 12 ms, because every call paused the OpenMP team
(`omp_pause_resource_all`) and the next parallel region paid a wake-up
that moved by a few milliseconds. The orthogonal walk no longer pauses
the team. It widens the affinity mask and leaves the workers under the
passive wait. After two warm-ups the eight samples sit between 7.16 ms
and 10.03 ms (median 8.56). mdapy on the same size and width has median
11.92 ms.

A reused q_lm row was also adding the previous frame onto the next, so
a second call drifted off the ideal-ice value 0.509175 (l = 4) and
0.628539 (l = 6). The row is cleared at the start of each atom. Both
values are stable across eight samples. The raw transcript, including
the drifted pass that was replaced, is `discovery/v3-session.txt`.

The figshare nucleation deposit (doi:10.6084/m9.figshare.11448702) is
148 frames of 4096 molecules, not 13553. Timings use step 15677000 of
that file and `input/traj/interface_f0.lammpstrj` (864 atoms). On ideal
ice every code's CHILL+ count is the full cubic population. On the
nucleation frame and the interface, mdapy 2.0.0 and OVITO 3.17.2 agree
with each other, and `ovito-chill+` agrees with mdapy on every atom
(4096/4096 and 864/864). The default published rule does not: it keeps
the closed edges c_ij <= -0.8 and -0.35 <= c_ij <= 0.25 and the
neighbour test for interfacial ice. Those two frames then disagree with
OVITO on the water/interfacial boundary. The thresholds are not moved
to close that gap.

## Triclinic cutoff

A restricted triclinic cell is stored as the bound spans plus xy, xz,
yz. The cutoff CSR bins the reduced coordinates and walks the same
27-cell stencil as the orthorhombic list, at a search radius that
covers the Cartesian ball, then keeps the pairs whose Cartesian image
is inside the cutoff. q4, q6 and published CHILL+ use that list. On
one thread and 110592 molecules the orthorhombic build is 25.12 ms.
The same ice, deformed with the cell (xy = 4, xz = 1.5, yz = 0.8), is
25.68 ms. A Cartesian point set dropped into that tilted cell, which
is not the crystal of the cell, stays at 43.49 ms. Raw samples are
`discovery/v5-session.txt`.

thread, medians in ms:

| q4 | 45.14 | 49.84 | 64.75 |
| q6 | 48.49 | 58.00 | 78.66 |
| CHILL+ | 41.47 | 614.98 | 62.27 |

Eight threads: q4 12.79 / 12.03 / 13.45, q6 11.35 / 10.91 / 15.12,
CHILL+ 8.71 / 86.77 / 14.33. q4 and q6 agree with both codes to 1e-15,
and every atom is cubic under the published rule and under

Ideal ice of 4096 molecules, CHILL+, seams against mdapy: 1.54 ms
