A one-thread run keeps the cpu mask it was launched with and a single thread. Under `taskset -c 0` with `RAYON_NUM_THREADS` unset, the first neighbour, CHILL+, ring or cage call moved the process to every cpu the kernel allowed, and the linkcell search then started a Rayon pool across those cpus. The OpenMP bind fix now restores only the cpus of the OpenMP places, a one-thread width (`OMP_NUM_THREADS=1` or `seams_set_num_threads(1)`) runs linkcell's walks and fused k-nearest region on the calling thread, and executables linked against the library no longer carry a second copy of linkcell whose `lc_set_threads` shadowed the library's. `test_serial_affinity` checks the mask and the thread count under taskset.
