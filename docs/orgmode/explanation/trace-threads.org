#+TITLE: Signature-search thread controls
#+OPTIONS: toc:nil num:nil

Commit ~9896a478~ on ~perf/trace-threads~ retimes the hydrate signature
search at 1, 2, 4 and 8 threads, after the pool and the row placement
changed. The census at every width is the one-thread census. The rows
are ~benchmarks/trace-threads.csv~. ~docs/render_sitting.py~ writes the
tables, and ~meson test docs_trace_threads~ recomputes each median and
type-7 interquartile range from ~samples_ms~.

* The process

~scripts/paper_stats.py~ builds the environment for one width \(n\):

| variable | value |
|----------+-------|
| ~OMP_NUM_THREADS~ | \(n\) |
| ~OMP_DYNAMIC~ | ~FALSE~ |
| ~OMP_PROC_BIND~ | ~close~ |
| ~OMP_PLACES~ | ~cores~ |
| ~RAYON_NUM_THREADS~ | \(n\) |
| ~OPENBLAS_NUM_THREADS~, ~MKL_NUM_THREADS~, ~NUMEXPR_NUM_THREADS~ | ~1~ |

The process is pinned with ~taskset -c 0~ when \(n = 1\), and with
~taskset -c 0-(n-1)~ otherwise. One warm-up is dropped. Eight repeats
remain. The median of an even count is the mean of the two central
samples. The interquartile range is the type-7 upper quartile minus
the lower one. ~cores~ is the size of the affinity set. ~affinity~ is
~Cpus_allowed_list~. The ~commit~ column is the source commit the
sitting recorded.

* One pool, then the search

Each sample is one linkcell neighbour list, one depth-6 primitive-ring
network, and one combined search of \(5^{12}\), \(5^{12}6^{2}\) and
\(5^{12}6^{4}\).

Linkcell keeps one Rayon pool for the process. A later search with the
same width reuses it. A different width drops that pool before the new
one starts, so two widths never run together. Between searches the
workers sleep on Rayon's idle condvar. That is the passive wait for
the neighbour list. ~lc_set_threads~ chooses the width. Zero or one
runs on the calling thread.

OpenMP is left on the active wait. ~seams::prepareCompute~, which the
linkcell list calls, sets ~omp_set_dynamic(0)~ and does not set
~OMP_WAIT_POLICY~. Forcing OpenMP passive as well made the next region
wake on a spread of tens of milliseconds, which was the slow
eight-thread sample.

Below 4096 molecules the linkcell team is capped at four. A caller that
asked for eight threads still gets four workers on those cells, because
the list and the cage walk do not fill a wider team and the extra
workers show up as a slow sample. Crystals at or above 4096 molecules
keep the width the caller asked for. The ~threads~ column is the width
that was requested. On sI \(2\times2\times2\) (368 molecules) and
\(4\times4\times4\) (2944) the eight-thread median therefore sits next
to the four-thread median.

Neighbour rows are placed on the calling thread until the pair list
reaches \(2^{20}\) pairs. The parallel sort forks a team that has just
been idle through the linkcell search. Waking it costs more than
writing the rows on the caller until the list is that large.
~kParallelRowsMinAtoms~ (4096) still has to hold as well.

The cage index is merged from per-thread buckets in ring order.
~tests/test_trace_threads.cpp~ requires the closed-cage faces, and the
hexagonal and double-diamond cages, to match the one-thread result.
Membership is the sorted atom ids of each face, not the ring index.

~seams_set_num_threads~ is the installed way to set the OpenMP width
the next search reads.

* Every kernel

Commit ~848426f9~ sizes the team on every kernel, and the sitting at
~3c1f5ef1~ records it. The rows are ~benchmarks/pool-audit.csv~. Eight
kernels run on ideal ice Ic: primitive rings, local and cutoff \(q_4\)
and \(q_6\), CHILL+, the shell label, and one carried hop-ball update.
The sizes are 4096, 32768, 110592 and 884736 molecules. Each size is
32 rows, the eight kernels at 1, 2, 4 and 8 threads. One warm-up, then
eight timed calls. The fingerprint of a kernel is the same at every
width. ~meson test docs_pool_audit~ recomputes each median and type-7
interquartile range from ~samples_ms~.

~seams::teamFor~ is the width of a per-atom walk. Below 2048 atoms it
is one thread. Below 8192 atoms, when the caller asked for more than
four, it is four. At or above 8192 atoms it is the OpenMP width.
~seams::TeamWidth~ sets that width for the rest of the call and
restores the caller's width afterwards. Bond order, published CHILL+,
the k-nearest list, the shell label, and local \(q_l\) use it. Those
calls do not start a Rayon pool.

~seams::adoptThreads~ no longer pauses the OpenMP team and no longer
sets ~OMP_WAIT_POLICY~. It calls ~prepareCompute~, then
~lc_set_threads~. The linkcell pool is still one per process, and its
workers still sleep between searches. The OpenMP team is left running,
so the next region does not pay the wake-up that used to move by tens
of milliseconds.

A carried ring update uses ~sourceTeam~, not ~teamFor~. The work is
the changed sources. The update stays on the calling thread until
those sources fill the workers, about 80 sources per thread. Fewer
than that is a serial update, because the fork costs more than the
search. ~teamFor~ is a different rule: it would also put a crystal of
a few hundred molecules on one thread.

The linkcell cap below 4096 molecules, and the row placement below
\(2^{20}\) pairs, are the signature-search rules above. They are not
replaced by ~teamFor~.
