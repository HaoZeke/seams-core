Summary
mmCIFFormat::read dereferences label_entity_id when label_seq_id is "."
and that column was not declared. The writer in the same file omits
label_entity_id and stores "." for an atom that has no residue. Reading
the file just written crashes.

Site
subprojects/chemfiles/src/formats/mmCIF.cpp:313-317
label_seq_id is "." so the reader parses label_entity_id.
label_entity_id comes from map::find and is not checked against end().

The installed library's read function compares a byte with 0x2e ('.')
and, on equality, calls chemfiles::parse<long>. The faulting instruction
is a read through the index taken from that missing column.
